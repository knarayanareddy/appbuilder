## Findings ledger

**AB-01 — Medium, confirmed static: incomplete storage validation can break rendering.** [useCameraSettings.ts:84–100](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/hooks/useCameraSettings.ts#L84-L100) checks selected numeric fields but not enum/text fields and ends with `return true`; [lines 153–157](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/hooks/useCameraSettings.ts#L153-L157) spreads accepted values over defaults. For example, stored `{"focusMode":{}}` passes this validator, while [Viewfinder.tsx:271–275](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/components/Viewfinder.tsx#L271-L275) renders `settings.focusMode` as a child. A malformed or stale same-origin value can therefore cause a React render error. Validate and reconstruct all supported fields, including preset settings; test valid migration and invalid types without trusting TypeScript at runtime.

**AB-02 — Medium, confirmed static: gallery deletion is session-view state, not durable.** [GalleryView.tsx:6–30](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/components/GalleryView.tsx#L6-L30) shows generated shots and `const MOCK_SHOTS = generateMockShots();`; [lines 199–224](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/components/GalleryView.tsx#L199-L224) initialize local state and delete only from that state, using `const [shots, setShots] = useState` and `setShots(prev => prev.filter`; [App.tsx:105–108](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/App.tsx#L105-L108) conditionally mounts the gallery, so leaving and returning resets deletions. For a demo, label this reset; do not imply deletion of real images. A durable gallery is a separate owner-approved product feature.

**AB-03 — Medium, confirmed static: selections survive leaving selection mode.** [GalleryView.tsx:211–256](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/components/GalleryView.tsx#L211-L256) copies the set with `const next = new Set(prev);` and removes an individually toggled selected ID or adds it with `else next.add(id);`. In contrast, the mode toggle uses `onClick={() => setSelectionMode(!selectionMode)}` without clearing the remaining selection. The [overlay:95–102](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/components/GalleryView.tsx#L95-L102) and [thumbnail prop:293–302](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/components/GalleryView.tsx#L293-L302) keep markers for `isSelected={selectedIds.has(shot.id)}` while the count disappears outside selection mode. Individual deselection and component remount do clear relevant state; the defect is specifically retention across mode toggles, not retention until deletion alone. A user may later act on a selection retained across modes. Clear it on cancel or make retention explicit, and confirm deletion.

**AB-04 — Medium, confirmed static: recording timer restarts on view remount.** [App.tsx:64–76](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/App.tsx#L64-L76) renders `Viewfinder` only on the camera tab, while [useCameraSettings.ts:160–205](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/hooks/useCameraSettings.ts#L160-L205) holds the parent state with `const [isRecording, setIsRecording] = useState(false);` and `setIsRecording((prev) => !prev);`; the view’s [lines 169–178](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/components/Viewfinder.tsx#L169-L178) reset elapsed time with `setElapsedSeconds(0);` whenever a mounted view sees recording. Returning to that tab resets the simulated timer although recording state lives in the parent hook. Make elapsed time derive from a stable start time or stop the simulation on exit, according to a documented product decision.

**AB-05 — Medium, historical CI failure; root cause unverified.** The collected [Actions run 41607576893](https://github.com/knarayanareddy/appbuilder/actions/runs/41607576893) records `conclusion: failure` for the **same pinned SHA**; the older [run 41604549807](https://github.com/knarayanareddy/appbuilder/actions/runs/41604549807) belongs to `4509949482f2c348d0f56cddeac9a3fd40064457`. Step logs were not inspected; no cause or present-day branch status is inferred. The [workflow:21–34](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/.github/workflows/ci.yml#L21-L34) includes `run: npm ci`, type-check, lint, tests and build. Reproduce with approved access and repair the actual failing step without weakening gates.

**AB-06 — Medium, confirmed static accessibility gap.** The [control toggle in App.tsx:80–89](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/App.tsx#L80-L89) has only chevron icons and no accessible name or expanded state, with `"onClick={() => setControlBarCollapsed(!controlBarCollapsed)}"`; the [shutter in Viewfinder.tsx:119–156](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/components/Viewfinder.tsx#L119-L156) likewise has no textual label, with `"onClick={isVideoMode ? toggleRecording : triggerShutter}"` and no `aria-label` on the button. Assistive technology cannot reliably identify these controls; add names, state and keyboard/screen-reader checks, including other icon controls.

**AB-07 — Low, confirmed static: simulated outputs look operational.** The [header:46–60](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/App.tsx#L46-L60) hardcodes `GPS`, `78%`, and `128GB`; the [detail actions:133–148](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/components/GalleryView.tsx#L133-L148) share the page URL and alert `Download started (mock image — no real asset to download).` The README disclaimer alone may not reach a person using the UI. Label simulation prominently and make mock actions honest.

## Five-discipline assessment

1. **Correctness:** AB-01–04 are direct source conclusions, not runtime reproductions. [useCameraSettings.ts:199–205](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/hooks/useCameraSettings.ts#L199-L205) changes animation/recording state, not media files.
2. **Testing:** [App.test.tsx:7–14](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/App.test.tsx#L7-L14) checks shell text; [GalleryView.test.tsx:25–29](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/components/GalleryView.test.tsx#L25-L29) calls a filter but asserts only that `shots` remains visible. These tests do not establish the behaviors above; other tests were not comprehensively assessed. [vitest.config.ts:5–10](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/vitest.config.ts#L5-L10) uses jsdom, not Android hardware.
3. **Operations:** AB-05 blocks confidence in the release gate. [workflow:13–19](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/.github/workflows/ci.yml#L13-L19) uses mutable action version tags and Node 20; action pinning and supported runtime compatibility require review, not an asserted exploit. Release hosting, signing and restore procedures were not inspected.
4. **OWASP/security:** No authentication or authorization boundary is visible in the sampled entry and local settings hook; do not infer that no other service exists. Injection sinks, CSP, credentials, lockfile integrity and dependency advisories were not fully inspected. [useCameraSettings.ts:113–134](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/hooks/useCameraSettings.ts#L113-L134) parses and persists browser storage and silently ignores write failures; [lines 169–172](https://github.com/knarayanareddy/appbuilder/blob/5029d899af89ee273306182871de6122a868915f/src/hooks/useCameraSettings.ts#L169-L172) writes settings and presets. Location is a possible setting, so shared-device retention and disclosure need an explicit policy; no actual secret leak is established. Browser storage is not a secret vault.
5. **UI/UX:** AB-06–07 require accessible controls and truthful simulation cues. Color contrast, focus order, target size, viewport and real Android/browser behavior are unverified; no compliance claim is made.

## Production blockers and owner decisions

Decide demo versus real capture; intended Android/browser delivery and supported devices; whether photo/location data may persist; and who owns release credentials, signing, hosting and recovery. Real capture, permissions, durable storage, export and device verification are not accepted features on this evidence. Resolve CI and the listed user-facing defects before even presenting a reliable demo. A production launch needs a separate security and device acceptance gate, not this review as certification.
